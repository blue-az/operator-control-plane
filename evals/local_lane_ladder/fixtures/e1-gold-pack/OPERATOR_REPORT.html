The two results

Summary

Above ~14B the fixtures are saturated. Seven models from 14B to 32B were run under identical controls; 62 of 63 cells passed. Every model clears them, so the set cannot rank seats and must not be cited as if it can.

Below ~12B they discriminate sharply, and monotonically. Five models from 3.4B to 14.8B score 8/18, 9/18, 13/18, 17/18, 18/18 — ordered by parameter count without exception. The failures are genuine: 19 of 25 are “the tool ran and did the wrong thing”, not harness artifacts.

Reaching a state where those numbers mean anything required fixing three defects in the harness itself, each of which had been silently biasing results. That work is documented below, because it bears on how much weight the tables deserve.

Method

What is measured, and how

Three plan-shaped (L2) fixtures, each graded by a machine-checkable postcondition that inspects the resulting files — never the model’s narration or a self-reported success. Every trial runs against a disposable temp fixture, so no real repository is touched. Every cell retains a full trace: raw stdout and stderr, exact argv, prompt, revision, and grade outcome.

Fixtures and their deterministic checks
TaskPostcondition — the only thing scored
alias-addExact line present in bash/.bash_aliases
config-value-changeNew value present and stale value absent
function-addImporting and calling square(4) returns 16

L2 means plan-shaped prompting: exact paths, anchored edits, one tool call per step, an explicit success criterion, bounded scope. All models ran fully GPU-resident at num_ctx 16384 with a uniform system prompt and identical sampling.

The instrument had to be repaired first

Three defects, each silently biasing results

These were found in sequence, each exposed by fixing the one before it. They are listed because a reader should know the earlier numbers were not merely noisy but systematically wrong, and why the current ones are not.

Harness defects found and fixed
DefectEffect on measurement
Tool-call extraction used a greedy brace span from the first { to the last } A response carrying two objects produced an unparseable span, so a correct tool call was returned as prose and nothing dispatched. Confounded 5 of 45 cells across two model families.
The strict-JSON system prompt was gated on a substring of the model name ("26b" in model) One model received an instruction its comparators did not — and it speaks directly to the emission behaviour being graded. Every cross-model comparison before this was confounded.
No sampling or context control at all was sent to the model server Context came from each model’s own defaults, so it differed per model and pushed a 32B model into CPU spill. Temperature was unpinned, making every cell a fresh draw.

All three are fixed, with tests, and the fix for each is covered by regression cases built from the verbatim payloads that failed.

What actually fails

The finding

Reviewer’s attention

The first capability to break is not tool-calling and not code generation — small models manage both. It is carrying an exact literal path from the prompt into the tool call.

The prompt names the file explicitly as bash/.bash_aliases. The models below the knee drop the directory prefix and write to a path that does not exist:

granite4 · 3.4B 0/6 
[Model requests tool call: patch_file]
{
  "tool": "patch_file",
  "path": ".bash_aliases",
  "target_content": "alias nv='nvidia-smi'",
  ...
}

[Tool Output]
Error: File not found: .bash_aliases
qwen2.5-coder · 14.8B 6/6 
[Model requests tool call: patch_file]
{
  "tool": "patch_file",
  "path": "bash/.bash_aliases",
  "target_content": "alias nv='nvidia-smi'",
  ...
}

[Tool Output]
Successfully patched bash/.bash_aliases.

llama3.1:8b compounds it by also truncating the anchor alias nv='nvidia-smi' to alias nv=. In every case the tool errored loudly rather than silently succeeding — the harness behaved correctly and the models were simply wrong.

It decays with scale rather than switching on

Path-fidelity failures on this fixture run roughly 6/6, 5/6, 4/6, 0/6, 0/6 from 3.4B to 14.8B — and the same error still appears once at 26B. This is a probability that falls with model size, not a threshold that is crossed. A larger model does not make the failure impossible; it makes it rare.

This matters for anyone relying on exact-path instructions: the failure is silent in intent and loud only because the file happened not to exist. An edit to a path that does exist would have succeeded against the wrong file.

The fixtures themselves are now graded

Instrument quality

Discriminating power across 3.4B–32B
FixtureVerdict
alias-add The discriminator. Sharp cliff between 8B and 12B; carries essentially all the signal.
config-value-change Saturated even at 3.4B (6/6). Carries no information at any size tested. Retire or harden.
function-add Weak and non-monotonic — an 8B model (6/6) outscores an 11.9B one (5/6).

That config-value-change passes 6/6 on a 3.4B model while alias-add scores 0/6 is itself informative. Both are single anchored string edits and look equivalent in the manifest. The difference is the path shape: config/settings.ini is conventional, while bash/.bash_aliases is a dotfile inside a directory — a form small models normalise away.

Two methodology results worth carrying elsewhere

Applies to any local-model benchmark

Temperature 0 is not a neutral control

Pinned for reproducibility, it produced a 6/9 for one model with every failure being the repeat-guard. Greedy decoding locks an agentic loop into re-issuing an identical tool call. Measured directly on the affected cell: 1/6 at temperature 0 against 6/6 at 0.8. Temperature 0 buys reproducibility by introducing a failure mode absent from real use, and it penalises loop-prone models specifically.

The seed is not honoured, and n=3 is weaker than it looks

The same seed on a high-entropy prompt produced different outputs on consecutive calls, so seed-based reproducibility is unavailable on this stack. Apparent determinism within a cell comes from the fixtures being low-entropy, not from seeding working. One model measured 3/3, 3/8, 8/8, 8/8, 6/6 on the same cell across separate windows — real variance lives across invocations, where a three-trial cell cannot see it.

Practical reading

If you have to choose a local seat today

  • Nothing below ~12B for plan-shaped edit work, and note it fails by writing to a path that does not exist rather than by refusing.
  • 12B is the knee, not the answer. 17/18, but at a 13.6s median — over 5× a 14.8B model’s 2.5s, for a worse score. Small does not mean fast.
  • qwen2.5-coder:14b is the value pick: 18/18 at 2.5s median in 9 GB.
  • Large models buy latency, not accuracy, on work of this size. Spend the VRAM only when the task exceeds what these fixtures represent.

Reproduction

For the verifying reviewer

OPERATOR_MACHINE=desktop python3 evals/local_lane_ladder/runner.py \
  --models <models> \
  --tasks alias-add config-value-change function-add \
  --levels L2 --trials 6 \
  --num-ctx 16384 --temperature 0.8 \
  --output <pack>/RESULTS.md \
  --state  <pack>/state.json \
  --trace-dir <pack>/traces

Completeness check — a short count means the pack is not scoreable:

ls <pack>/traces/*.json | wc -l

Each pack retains traces/ (one JSON per cell), state.json, RESULTS.md, FINDING.md, and evidence/ holding pre-run provenance and interval residency samples.

Open items

Recommended next actions

  1. Independent re-derive by a distinct identity, now spanning five packs. Required before any of this is registered as a claim.
  2. Retire or harden config-value-change. It has carried no information at any model size tested.
  3. Build one fixture above the ceiling — a multi-file edit, an anchor appearing more than once, four-plus dependent steps, or a repair loop after a failing test. Adding models to the current set produces more 9/9 rows and no information.
  4. Investigate cross-invocation variance directly, with many repetitions spread over time rather than more trials inside one window.
