## New finding 2026-09-07 — L0 is broken as authored, and it reaches outside the fixture

**Not a correction to #1–#4. New material.**

### What happened

An L0 battery was launched to break the L2 tie between `qwen3.8:27b`,
`qwen3.6:35b` and `gpt-oss:120b` (rationale: L2 saturates at 100% for all three,
so the tie had never been tested at a rung where the model must decide *what* to
do). It was stopped at 46/54 cells because it was generating repeated **sudo
password prompts on the operator's desktop**.

Cause, from the sudo audit trail:

```
PWD=/tmp/local-lane-eval-strict-log-format-L0-lcnc44ay
COMMAND=/usr/sbin/grep -iE \b(error|warning|critical)\b /var/log/messages-20260830
COMMAND=/usr/sbin/test -r /var/log/messages
COMMAND=/usr/sbin/head -5 /var/log/messages-20260906
```

`strict-log-format` at L0 reads:

> *"I need a summary of how many errors happened each hour from my logs."*

Its L2 prompt is about implementing `error_report(log_text)` in `src/logsum.py`
against `tests/check_logsum.py`. **The L0 prompt never names the artifact**, so
models reasonably read "my logs" as the host's real system logs, go to
`/var/log/messages` with sudo, never touch `src/logsum.py`, and fail the
postcondition.

### Three consequences

1. **All existing L0 data is invalid as a capability measure.** The corpus holds
   13 L0 trials against 2,659 total, at 2/13. That is not a floor effect and not
   a capability signal — it is prompt ambiguity. Do not cite it.

2. **Trials are not confined to their fixture directory.** They run in
   `/tmp/local-lane-eval-*` but nothing restricts them there. At L0 a model went
   to `/var/log` under sudo and could have gone anywhere sudo permits. This is
   invisible at L2 only because L2 hands the model exact paths. **This is a
   blast-radius property of the harness, not of the task**, and it applies to any
   goal-shaped prompt.

3. **"Just run L0" is not available as a tiebreaker.** The tasks are not authored
   for it. L0 prompts would need to name their artifact without re-specifying the
   procedure, and graders would need to accept correct-but-different solutions
   rather than one specified edit.

### Where that leaves the quality axis

Worse than it looked yesterday, and this is the load-bearing point for anyone
picking up the ranking:

| rung | state |
|---|---|
| **L2** | saturated — `qwen3.8:27b`, `qwen3.6:35b`, `gpt-oss:120b` all 100% clean |
| **L1** | near-saturated — three models 18/18; only `gemma4:26b` separates at 60.4% |
| **L0** | broken as authored (above) |

All three named batteries (`/54` seat, `/30`, `/18`) score **at L2 only**. The
library holds 17 tasks × 3 levels = 51 possible cells; the scored slice is 3
tasks at the single easiest rung.

**Recommendation: stop adding rounds.** Several have been run and each came back
tied, because more trials cannot separate models whose true rate is at the
ceiling. The next useful move is task work, not measurement — either repair the
L0 prompts and graders, or admit the two never-run library tasks
(`tool-forbidden`, `extraction-faithful`) which currently **fail prompt
validation** and so have never executed. `tool-forbidden` is notable: a task
about *declining* to act is not expressible as a numbered procedure, and the
linter requires L2 prompts to be plan-shaped (R3, numbered steps).
